현재 Controller 는 인터페이스, 애너테이션 두 가지 방식으로 작동한다.

인터페이스 기반 Controller 는 빈 이름에 url 을 매핑하는 방식으로 등록, 사용된다.
애너테이션 기반 Controller 는 url 과 HTTP Method 모두 매핑하는 방식으로 사용된다.

매핑 방식이 다름에도 DispatcherServlet 에서 구분 없이 Controller 를 찾는 방법을 고민해보자.

## 요구사항

### 1. 인터페이스 기반 컨트롤러 매핑

인터페이스 기반 컨트롤러 빈 생성 시 URL 매핑과 URL 에 알맞은 컨트롤러를 찾아주는 역할의 클래스를 만들자.

### 2. 애너테이션 기반 컨트롤러 매핑

애너테이션 기반 컨트롤러 빈 생성 시 URL, HTTP Method 매핑과 URL 에 알맞은 컨트롤러를 찾아주는 역할의 클래스를 만들자

--- 

DiapatcherServlet 에서 요청에 맞는 적절한 Controller 를 찾을 수 있다. 하지만 해당 Controller 가 인터페이스 기반인지, 애너테이션 기반인지에 따라 실행 방법이 다르다.
DispatcherServlet 에서 여전히 Controller 를 실행하게 되면 Controller 타입마다 실행 방법이 달라 코드가 복잡해질 것이다. 이를 해소하기 위해 실행 책임을 분리해보자.

## 요구사항

### 1. 인터페이스 Controller 실행

인터페이스 Controller 는 적절한 파라미터와 함께 invoke 를 통해 실행할 수 있다. 이 방법으로 실행하는 클래스를 만들어보자.

### 2. 애너테이션 Controller 실행

애너테이션 Controller 는 적절한 파라미터와 함께 Method 를 실행할 instance 가 있어야 실행할 수 있다. 이 방법으로 실행하는 클래스를 만들어보자.
