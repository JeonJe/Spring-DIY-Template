현재 프레임워크의 Controller 인터페이스에는 몇 가지 한계가 있다.

Http Method 별 로직을 분리시킬 수도 없고 파라미터로 ServletRequest, ServletResponse 를 직접 받아 원하는 정보를 가져오거나 응답에 명시해야 한다.

인터페이스를 구현하지 않고도 런타임에서 컨트롤러 메서드의 URL 정보, 파라미터, 리턴 값을 알 수 있다면 조금 더 유연한 컨트롤러를 사용할 수 있을 것 같다.
지난 시간에 학습한 리플렉션을 이용하여 컨트롤러를 구현하는 방법에 대해서 고민해보자.

## 요구사항

### 1. Controller 동적 생성을 위한 애너테이션

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Target({ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
@Component
public @interface Controller {
}
```

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Target({ElementType.TYPE, ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
public @interface RequestMapping {
    String value() default "";
    RequestMethod[] methods() default {};
}
```

```java
public enum RequestMethod {
    GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS, TRACE
}
```

### 2. @Component 기반 컨트롤러 동적 생성

애너테이션 기반의 컨트롤러는 URL 을 애너테이션에 선언해 컴파일 시점에 URL 과 매핑될 수 있게 구현할 예정이다. 또한 HTTP 메서드도 애너테이션을 통해 매핑될 수 있게 하여 컨트롤러 자체는 본 역할에 더욱 집중할 수 있게 된다.

런타임에서 동적으로 컨트롤러와 컨트롤러 메서드를 빈으로 생성하고 URL 과 매핑해주자.

### 3. 인터페이스 기반 컨트롤러와 애너테이션 기반 컨트롤러 추상화

이전에 구현한 인터페이스 기반 컨트롤러와 이번에 새롭게 구현한 애너테이션 기반 컨트롤러 모두 구분 없이 사용하도록 해보자.

나아가 새로운 방식의 컨트롤러를 도입하더라도 문제가 없게 추상화를 해보자.

### 4. 강의 서버 컨트롤러 마이그레이션

기존 인터페이스 기반으로 구현한 강의 컨트롤러를 애너테이션 기반 컨트롤러로 변경하자.

변경 후 페이지 조회가 정상적으로 보이는지까지 확인해보자.
